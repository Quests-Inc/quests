# Карта: деревья, расклады и зоны

Шапка карты разделяет поиск для добавления дерева, параметры **нового** дерева, общие фильтры видимости и действия.
Раскладка и глубина в меню «Новое дерево» действуют при добавлении. Для деревьев на холсте используйте ПКМ по карточке
или выделению → «Настройки деревьев». Общие карточки принадлежат первому дереву, которое их показало;
при выборе самого корня изменяется именно это дерево.

## Самостоятельные расклады

Полотно всегда принадлежит одному раскладу. Явный переход к карте из сущности создаёт временный расклад;
переключение на уже открытый расклад восстанавливает его состояние. Временные расклады живут только в памяти вкладки,
не записываются в localStorage и теряются при перезагрузке. Кнопка сохранения делает текущий временный расклад
постоянным. Постоянные расклады сохраняют изменения автоматически с задержкой 700 мс; уход на другой расклад
дожидается записи предыдущего. Чужой расклад больше нельзя перезаписать содержимым текущего через кнопку в строке.

«+» создаёт пустой постоянный расклад: текст поля становится именем, пустое/пробельное поле —
«Новая раскладка (N)» с первым свободным положительным N. Это не копирование текущей карты. Поле одновременно
фильтрует список по подстроке названия без учёта регистра. Активный расклад, не подошедший под фильтр,
показан отдельно под пометкой «Открыт · вне фильтра» и не дублируется в результатах.

В формат v1 добавлено необязательное `draft_scope` — UUID собственного черновика. Позиции, размеры карточек, корни,
фильтры, раскрытия, зоны и камера восстанавливаются вместе. Старый сохранённый v1 открывается с новым UUID и
получает его при первом сохранении; общий браузерный набор настроек больше не подмешивается. Активный постоянный
расклад отмечен параметром `layout` в URL и восстанавливается после рефреша. Временный такого параметра не имеет.
Обновление каталога сущностей не создаёт временный расклад: для явного перехода используется отдельный счётчик навигации.

Запросы `/api/graph-draft` и его подмаршрутов получают `?layout=UUID`; операции, дополнительные корни, сохранение,
отмена и удаление операций изолированы этим ключом внутри пространства (миграция 0043). Ответ старого запроса
не подменяет черновик после переключения. API без параметра оставлен для совместимости и по-прежнему видит старый
общий черновик; новая карта в него не пишет. При клонировании JSON расклада внешним клиентом нужно удалить
`draft_scope`, чтобы новая карта получила свой UUID, а не разделила чужой журнал.

## Изображения и буфер

Растровые вложения растягиваются уголком как заметки; размеры сохраняются в раскладе, пропорции самого изображения
сохраняет `object-fit: contain`. Файл показывается на полотне, не обрезается под квадрат карточки.

`preview=1` сам по себе **не** уменьшает оригинал. Для карты добавлен `thumb=128|256|512|1024|2048` — максимальная
сторона уменьшенной версии. Непрозрачные превью сжимаются в JPEG quality 75, прозрачные — в PNG. GIF-превью показывает
первый кадр. Оригинал не меняется. У варианта свой ETag; кэш сервера ограничен 24 МиБ / 512 записями, создание —
двумя параллельными задачами, вход — 25 МиБ и 20 млн пикселей. Ошибка превью не запускает тяжёлую загрузку автоматически:
карточка предлагает явно загрузить оригинал.

Качество на клиенте зависит от размера карточки в экранных пикселях, масштаба, devicePixelRatio и пересечения с окном.
Уровни укрупнены; увеличение запрашивается после 160 мс, уменьшение в уже смонтированной карточке не вызывает повторных
загрузок. За пределами экрана карточки по-прежнему отсекаются. Оригинал нужен только при экранном размере выше 2048 пикселей
либо по явному запросу после ошибки превью.

Paste с файлами при активной карте загружает их через обычные проверки квоты/антивируса как вложения пространства
(`owner_type=workspace`), не привязанные к заметке или квесту, и добавляет карточки в текущий расклад. В полях ввода
вставка не перехватывается. Удаление карточки или потеря временного расклада не удаляют файл; он остаётся в разделе
«Вложения → Без привязки». Для загрузки на стенде должны быть настроены настоящие WebDAV и ClamAV, как для обычных
вложений; эти проверки не отключаются.

Замер на синтетическом PNG 1600×900 (Go benchmark, i7-13700F): оригинал 142942 байта, вариант 256 — 9251 байт
(примерно на 93,5% меньше). Построение — около 12,1 мс и 6,9 МиБ выделений на операцию; прогретый lookup кэша —
около 14 нс, без выделений. Это микробенчмарк преобразования/кэша, не время HTTP-запроса или открытия страницы:
первый запрос дополнительно читает оригинал из WebDAV, каждый запрос проверяет метаданные/доступ. Условный запрос
с актуальным ETag отдаёт 304 без тела. Реальное отношение размеров зависит от изображения и формата оригинала.

## Упрощённые заметки

При скрытии Markdown заметка сохраняет заголовок и полупрозрачный силуэт строк. Это приближённая структура,
а не точная копия браузерной вёрстки: исходник ограничен 4096 символами, переносы моделируются блоками по 64 символа,
не более 32 полосок. Все полоски объединены в один SVG path (два DOM-элемента на карточку), кэш — 400 текстов.
Markdown и DOM не разбираются заново при каждом движении камеры.

Локальный замер в Bun, 400 разных текстов: построение всех силуэтов около 14,1 мс; получение из прогретого кэша —
около 0,09 мс на те же 400 карточек. Это измерение вычислений, не FPS браузера. Дешёвый ограниченный силуэт сохраняет
ориентиры без возвращения полного Markdown на отдалённой карте. Измерение не обещает точного совпадения длин визуально
перенесённых строк, шрифтов и форматирования.

## Зоны

«＋ Зона» включает рисование прямоугольной области на холсте. Потяните по карте; Esc, ПКМ или отмена указателя
отменяют жест. Зона должна иметь ширину и высоту не меньше 40 единиц карты. Потяните подпись, чтобы переместить
зону, или нижний правый угол, чтобы растянуть. Клик по подписи открывает название, цвет, размеры и удаление.
При перетаскивании меняется только предпросмотр; координаты сохраняются при отпускании указателя.

Зоны — независимые аннотации: они не группируют сущности и не перемещают карточки. Слой находится под карточками,
масштабируется и перемещается вместе с картой. Зоны принадлежат текущему раскладу и входят в его состояние;
при открытии старого расклада список зон пустой. Очистка карты также очищает зоны.
Максимум 200 зон, подпись до 120 символов. Свободное рисование пока не реализовано.

## MCP

`get_graph` читает связи вокруг сущности. Новый `graph_layout` работает с **личными сохранёнными раскладами** активного
пространства, а не с открытым холстом браузера:

- `list`: список; `get` + `id`: полный JSON состояния.
- `create` + `title`, `state`: новый расклад.
- `diff` + `id`, `state`: добавленные/убранные сущности; `legacy` сообщает о приблизительном составе старого расклада.
- `update` + `id`, `state`: предварительная разница без записи (`requires_confirmation: true`). Покажите её пользователю;
  только после одобрения повторите тот же запрос с `confirm: true`. Переименование через `title` без `state` записывается сразу.
- `delete` + `id`: предварительное подтверждение, удаление выполняется только с `confirm: true`.

`state` заменяется целиком, поэтому сначала прочитайте его через `get` и сохраните неизвестные поля.
Версия формата остаётся `v: 1`; новые необязательные поля совместимы со старыми раскладами.

```json
{
  "v": 1,
  "center": {"type": "quest", "id": 5},
  "roots": [{"type": "note", "id": 3}],
  "trees": {
    "quest:5": {"depth": 2, "layout": "tree"},
    "note:3": {"depth": 1, "layout": "radial"}
  },
  "depth": 2,
  "layout": "tree",
  "statuses": ["active"],
  "types": ["questline", "quest", "step", "note", "attachment"],
  "hidden": [],
  "expand": [],
  "folds": {"expanded": [], "loose": []},
  "positions": {"quest:5": {"x": 0, "y": 0}, "note:3": {"x": 600, "y": 0}},
  "sizes": {},
  "entities": [{"key": "quest:5", "title": "Квест"}, {"key": "note:3", "title": "Заметка"}],
  "zones": [{"id": "study", "title": "Учёба", "color": "#6a8fbf", "x": -100, "y": -100, "w": 900, "h": 500}],
  "view": {"cx": 300, "cy": 0, "k": 1}
}
```

`trees`: глубина 1–3, режим `tree`, `down`, `radial`, `layers` или `free`.
`entities`: состав видимой карты до сворачивания групп, без черновика и синтетических `cluster:*`; это источник разницы.
`positions` может содержать прежние позиции временно скрытых карточек, поэтому не заменяет `entities`.
`zones`: уникальные строковые `id`, подпись, цвет `#RRGGBB`, координаты левого верхнего угла и размеры в координатах мира.
Сервер хранит JSON непрозрачно, с действующими ограничениями размера и изоляцией пользователя/пространства.
